# ADR-013 proposal: document edits and durable revisions

**Awaiting owner approval.** This is a logical design and acceptance baseline, not a frozen wire format or DDL. Applies on `feature/m03-document-engine` from `8b5c24dbafbfbb78123c22ab819cd581897a2245`. Keeps ADR-003/004/008/010/012; no change to ADR-002/006. No production spatial index, renderer migration or persistent undo.

## What is authoritative?

One platform-independent C++ Document owns immutable vector records, an ID lookup and an ordered sequence. JNI routes events; GL and the store consume changes, neither owns the live model. A record contains `(document UUID, positive int63 stroke ID)`, content revision, geometry revision, versioned tool and brush identifiers, straight RGB and separate opacity (v1 diagnostic spline blue, opaque by default; comparison colors are view styles), captured base **radius** in world units, pressure law and recipe version, actual filter coefficients, capture settings and ordered accepted samples. World coordinates and monotonic seconds are binary64, pressure and projected tilt radians binary32. One world unit is one view pixel at zoom 1. No density conversion, time synthesis, sorting or de-duplication. Record original tool separately from the selected brush. Doubles on CPU; existing float-world draw path remains an explicitly limited diagnostic, not a new persistent coordinate model.

M02 `NativeBridge.sample` maps `pan + pixel/zoom` **before** the filter. `begin` fixes the float result of `1.9/zoom`; radius scales thereafter with the camera, not with the display. Capture that exact value. V1 pins the pressure law, filter reset/tie rules, fitter parameters, incremental knot/pressure peak handling, tessellation tolerance/step cap, float rounding points, stable/tail emission timing, connector threshold and final disc. Camera zoom during subsequent samples affects deviation telemetry, not the committed path. Ordered raw input **plus this recipe**, not raw points alone or a batch refit, is the proposed source. Extract the existing streaming builder including finalization; replay accepted samples in arrival order. No stored spline or meshes proposed for v1: each spline input (including speed) comes from the reset filter and accepted sequence, and emission is a function of its prefix. Prove this on all representations; a parity failure blocks shipping, not permission to silently normalize old ink. Keep v1 reader/builder when defaults change; unknown recipes fail non-destructively. Cached conservative bounds include all diagnostic representations, widths, terminal geometry and AA margin; recompute/validate before relying on loaded bounds.

## Identity, edits and ownership

- Create UUIDv4 with OS entropy and exclusive catalog insertion (retry collision; never open an existing document as new). Reserve monotonic ID blocks in durable metadata off-thread **before** issue; gaps on crash, failed edit or unused reservation are legal. Never rewind allocation on Clear, delete, history branch or load. Reject duplicate or exhausted IDs without mutation; no wrapping. Same policy for revision exhaustion. No dependence on GL generations.
- Sequence, not numeric ID, defines paint order. Append at tail in commit order. Keep stable nodes with predecessor/successor identities and endpoints, both in memory and in logical storage. Replace in place for one-to-one transform; split atomically removes original and splices fresh IDs in fragment traversal order between its former neighbors. Undo restores original slot(s); bounded page traversal from a node, O(1) expected lookup/splice per touched node. Future spatial index stores references; a derived order-rank structure can accelerate comparing sparse candidates without changing persistence. Validate linked order is one reciprocal, acyclic chain reaching exactly all records at open.
- One active builder per input transaction bound to a document session token. Reject duplicate begin. Preflight resources, history, change delivery and queue admission before publishing any mutation. End transfers ownership once, empty/duplicate end never appends; cancel discards. Commands specify expected document/base revision and affected IDs. Missing ID, conflict, invalid transform, size/allocation failure: no partial mutation, no history movement. Empty/no-change is success without revision. Explicit edit actions cancel active input first; failed command never commits cancelled ink. Switch validates incoming document off-thread and flushes old edits before activation; cancel active on switch request, gate edits during cutover. Failed open leaves previous document intact.
- One monotonically advancing document revision per successful group, including undo/redo. Each changed/reattached record receives current revision as content token; geometry token changes for new/replaced/restored geometry, not for color-only changes or neighbors' relinking. Undo restores exact sample/style/ID/order values, not old freshness tokens. Geometry transform uses checked finite affine mapping of canonical path via versioned post-reconstruction transform (initial primitive translation, width unchanged); never refilter translated points to approximate transformed ink.
- History is session-local. A group holds reversible splices and shared canonical payloads, not meshes; new successful edit clears redo. Proposed caps 128 groups / 64 MiB total, charge allocated capacities, structure and reachable payloads conservatively, including detached nodes. Evict oldest eligible groups; if one command cannot itself be retained, **reject before edit** with an explicit budget error (Clear is never silently irreversible). Clear can detach/swap a sequence and ID table with total charged bytes maintained incrementally; undo can reattach, not clone all samples. Whole-stroke erase targets topmost actually hit ink, reverse draw order after bounds rejection, tapered segments and dots in world coordinates with view-scaled hit tolerance; swept gesture groups distinct hits into one undo. A miss changes nothing. Linear hit testing is an edit-time M03 limitation, not another per-frame scan.

## Backend choice and proposed storage boundary

The accepted physical long stroke had 41,633 samples. At 36 explicit bytes/sample this is 1,498,788 bytes before metadata; a 100k-document of even 8-sample strokes has 28.8 MB of samples. An atomic temp snapshot + file sync + rename + directory sync has a straightforward old/new recovery story but a one-dot edit must rewrite those other bytes and hold a consistent whole-document view. A worker changes latency, not write amplification. Useful as eventual export, not as autosave. SQLite costs B-tree indexes, journal traffic and runtime-specific I/O; page writes/checkpoint spikes must be measured, not assumed constant. It already provides tested multi-row rollback, transactions and bounded record queries; no custom journal, spatial DB or NDK-private SQLite linkage.

**Recommend app-private platform SQLite via Java on API 28+,** one serialized application-lifetime worker, native typed change/read abstraction, bounded pull/push chunks across JNI; host codec/core harness and actual Android backend tests, not a host substitute for framework recovery. One database with catalog/last-open pointer, document metadata (endpoints, count, versions, reservation ceiling, durable revision), per-document keyed records with neighbor links and versioned style/recipe, indexed fixed-maximum sample chunks keyed by stroke and ordinal. Foreign keys on. Normalized record references, not positional offsets. Version 1 explicit little-endian field encoding, field widths/units and lengths specified and fixture-tested after approval, per-record integrity checksum covering canonical fields and ordered chunks; validate links and metadata separately. No struct dumps or GPU data. Initial limits: 1,000,000 samples/stroke as at input, 64 KiB/chunk, checked aggregate counts and bytes before allocation, reject nonfinite/out-of-domain fields, duplicate keys, inconsistent counts/ordinals, unsupported transforms/versions or bad checksums. Stream rows with bounded cursor projections, no single huge row/JNI array. Apply explicit resident byte budget based on physical memory and checked capacity accounting before open; oversize is a reported capacity error, not truncation. Use bounded sequential load/build with cancellation. M04 can page records without changing identities.

One SQL transaction per command/group, including neighbor repairs, payload chunks and compare-and-set durable base revision. Clear may touch many rows, inherently proportional on disk; no intermediate visible revision. WAL and synchronous FULL on writer, verify settings, foreign keys and supported platform behavior. Durability = SQLite successful commit with these settings (subject to filesystem/device honoring sync); UI notification only after success. On ambiguous result, reopen/check committed revision and group token before retry; no blind duplicate apply. ID reservation transactions are independent of edit revisions. Last-open pointer changes transactionally only after valid creation/open. Disable framework destructive corruption recovery; fail closed on unknown schema/recipe or invalid chain/payload, preserve DB **and WAL/sidecars**, show error with retry/open-other, never fallback to empty/overwrite. No existing application format to import. Later migrations require recognized source version, verified backup and transactional upgrade with failure leaving source usable; otherwise refuse.

Reserve queue credits before visible commit: FIFO immutable deltas, maximum 32 including in-flight, 64 MiB charged pinned payload/metadata, separate 64 KiB streaming buffers. Clear delta uses document/base token rather than enumerating deleted samples; inverse bulk restore references retained roots and is charged. Apply history and pending-save budgets independently; no hidden root pin outside accounting. Full queue rejects an edit with visible busy/retry status rather than dropping deltas or blocking the pen. Worker never takes input mutex for encoding, JNI bulk copy, DB I/O or tessellation. Track visible/dirty/durable per document; flush returns async barrier for target revision, not a UI-thread wait. FIFO retry with capped backoff and explicit retry on persistent failure; keep bounded pending work, stop admitting when full. Pause cancels live and requests flush; rotation doesn't spawn a second writer, graceful close drains or reports failure; OS kill can lose only non-durable edits. Cancel/supersede load and reconstruction by token, never discard an acknowledged edit. No durable-history promise after restart.

## Renderer and integration

Replace `finishedEpoch/glFinishedCount` append publication with ordered change groups keyed by session/ID/content/geometry revision. Maintain GL-thread order nodes and resource map; patch touched records only. A style change reuses geometry. New live completion may transfer derived payload and matching successful live VBO prefixes once; canonical/history references never retain them. Reject stale mesh work before install (session, geometry revision, current membership and GL generation). GL thread retires superseded buffers, drops invalid names without deleting into a new context; after recreation rebuild from current authoritative state via bounded chunks. Whole reset only for switch/reset/recovery, not ordinary edits. Bound outstanding derived work and change delivery; admission/backpressure rather than missed edits, bounded reclamation outside lock. Keep existing visible traversal and coverage resolve; supply record color/opacity for primary ink without changing diagnostic overlay defaults. Publish a group atomically (no partially drawn replacement). On-demand frames only for interaction or pending publication.

## Implementation sequence after approval

1. C++ records, builder, transaction preflight, ordered changes and budgeted history; reference-model and fault tests.
2. Storage abstraction, validated codec, Android worker/SQLite adapter, failure and crash harness; measure incremental writes.
3. Wire pen-up, erase and commands, GL cache patches, pause/resume/switch and error/status controls into the existing Java/JNI app. No second drawing demo.
4. Integrated regressions and matched benchmarks; independent diff reviews for correctness/storage, graphics and performance (at most two concurrent). Fix or report blockers, archive APK/hash, supply tablet procedure and stop for written acceptance.
