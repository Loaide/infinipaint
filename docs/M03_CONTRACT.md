# M03 document and storage contract (v1)

[ADR-013](M03_PROPOSAL.md) controls these choices. The vector record, not rendered pixels, is the durable object.

**Keys and edits.** The catalog assigns random v4 document UUIDs. Within each UUID, zero is a link sentinel and positive signed 64-bit IDs come from exclusively committed 65,536-ID reservations. An abandoned reservation, cancelled stroke or crash can create gaps. IDs do not wrap or return to the allocator. Head/tail plus reciprocal `prev`/`next` links determine order; lookup uses a balanced tree, not iteration in ID order. After undo, the next successful new edit abandons redo. A group splices all of its records or none; translation is applied after reconstruction, not by refiltering translated samples. A color-only replacement of the same geometry retains its geometry revision. Undo restores logical content/slot/ID, not a superseded freshness token. Split inserts fragments at the deleted stroke's old location. The M04 `SparsePaintOrder` interface is derived and revision-checked; its sublinear-in-document-size sparse sort remains M04 work without a schema change.

**Pen and history.** Pen-down reserves an order node, ID, history destination, render notification nodes and one bounded save slot. Growth must fit history, queue and residency limits. The accepted prefix remains available on failure; pen-up transfers samples rather than rescanning them. Retry/discard is explicit. Successful end is exactly once; cancel never writes a record. History is limited by both retained capacities and group count (64 MiB/128 groups); oversized Clear is rejected, never irreversible. Same-session pause, rotation and EGL loss keep history; successful switch/reopen starts new history. Large undoable bulk edits beyond this budget require a later bounded external representation.

**Canonical wire bytes.** Unsigned fields below are 32-bit; floats are IEEE-754, explicitly little-endian. An 80-byte header stores header version, world-unit version, recipe ID, brush ID, original tool, float world-space base radius, three binary64 One-Euro coefficients (minimum cutoff, beta, derivative cutoff), four binary32 straight RGBA components, then binary64 translation X/Y. A 36-byte sample is binary64 world X, Y and monotonic seconds, then binary32 pressure, projected X/Y tilts. One world unit is a pixel at zoom 1. Ordered ties and stationary updates survive; there are no synthetic timestamps. The v1 streaming builder pins pressure mapping, filter/spline/tessellation and terminal connector/disc behavior. Match geometry and pixels on a matched build/backend; bit-identical shader/libm results across different drivers or architectures are not promised.

**Storage and durability.** `documents-v1.sqlite` lives in app-private no-backup storage. SQLite application ID `IPDC`, `user_version=1`. `document` carries revision, reserved ceiling, endpoints/count and independent camera state/sequence. `catalog` selects the last opened document. `stroke` holds IDs, links, revisions, header, sample count and digest. `chunk` holds contiguous ordinals of at most 1,820 whole samples (65,520 B). At most 1M samples per record, additionally subject to physical-memory admission. SHA-256 covers the header and ordered sample bytes; the loader separately checks reciprocal links, endpoints/count, IDs, revisions, ordinals, lengths and decoded numerical domains. There is no historical durable format to migrate; reject unknown formats without rewriting them.

One application-lifetime worker opens SQLite with a preserving corruption handler, verifies WAL/FULL/foreign keys on the writer connection, and applies one base-revision-checked SQL transaction per change group. Its commit token makes retry after commit-before-ack idempotent. Only successful commit is durable, subject to filesystem/device sync semantics. FIFO is limited to 32 entries including in-flight work and 64 MiB charged bytes. Save/retry is asynchronous; flush captures an edit revision and camera sequence. View metadata is independent of edit history and coalesces to one pending latest value. Missing previously initialized catalogs and corrupt/unsupported records produce errors rather than an empty replacement. A switch suspends admission, flushes the outgoing state, validates/reconstructs a candidate, durably selects it and swaps in its scene and camera together. Selection failure leaves the prior document editable.

**Memory and publication.** `R=min(physical RAM/16,384 MiB)`; swap/RAM Plus is not used. The logical limits for canonical and derived CPU data are approximately `R/8` and `R/3`. `working_set.hpp` additionally tests overlapping ownership against `3R`: unique vector payloads, completed CPU/VBO capacity, order metadata, active growth, reconstruction and candidate decoding, with reserved space for history, saves, bounded JNI/SQLite/Java staging and a delayed live upload. These are conservative admission estimates, **not** RSS or guaranteed GPU driver allocations. `ip-document` reports retained/peak charges; use process memory and SQLite measurements at the device gate. Bounded failure during a switch must preserve the current document. No production paging or residency index.

Ordinary GL updates follow touched links and geometry revisions; the GL thread alone retires valid names. A matching live VBO prefix can be adopted once. Context loss forgets names but preserves the CPU order/geometry. Sparse changes are applied before drawing in stable link order; unchanged records are not reuploaded. The diagnostic still traverses visible candidates linearly and renders at capture-scale precision. Expensive switch/rebuild and driver tails need tablet evidence; this is not M04 rendering validation.
