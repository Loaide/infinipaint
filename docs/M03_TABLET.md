# M03 isolated Android gate — do not run without device authorization

Use a named spare device/emulator first for instrumentation, then the owner's SM-X626B for the physical gate. Record model, Android build, refresh mode, resolution, physical RAM, power mode, thermal state, APK hashes and tested source SHA. The test target is **`com.infinipaint.demo.m03verify`**, not the owner's `com.infinipaint.demo`. The runner package ends in `.m03verify.test`. Neither installation, user-data removal, nor termination of an owner session is authorized by this procedure.

1. **Identity check:** inspect `aapt dump badging` on both `app/build/outputs/apk/m03Verify/*.apk` and `app/build/outputs/apk/androidTest/m03Verify/*.apk`. Stop on any package mismatch or an existing verification installation containing wanted data. The private crash-probe service exists only in the verification target. Keep the accepted M02 APK/captures unchanged.
2. **After explicit authorization** install only those two APKs on the named test device. Do not use `connectedAndroidTest` against a collection of attached devices; specify `adb -s SERIAL`. Do not clear either package. Record the instrumentation output (including failures/skips) and `IP_M03_SQL` / `IP_M03_MEMORY` logs:

   ```text
   adb -s SERIAL install app/build/outputs/apk/m03Verify/app-m03Verify.apk
   adb -s SERIAL install app/build/outputs/apk/androidTest/m03Verify/app-m03Verify-androidTest.apk
   adb -s SERIAL shell am instrument -w -r -e m03Scale true com.infinipaint.demo.m03verify.test/androidx.test.runner.AndroidJUnitRunner
   ```

   These installation commands are for a **fresh, authorized** verification environment. If already installed, stop rather than uninstalling or replacing anything. For the separately authorized physical session, launch `adb -s SERIAL shell am start -n com.infinipaint.demo.m03verify/com.infinipaint.demo.MainActivity` and follow steps 3–8.

   The tests use unique cache files. Recovery tests kill **only** a private `:recovery_probe` child, after the runner witnesses a specified boundary. Require old revision before write and during chunk insertion, new revision after SQL commit and after acknowledgement, with complete identity/order and payload. A normal close/reopen is not a process-death test. Preserve failing fixtures; do not “fix” failures by clearing data.
3. **Functional ink:** launch only the verification app, create a new document A from **Document**. Draw a dot, long curved line, stationary pressure change, pressure ramp and rapid tied-position sequence; try Light/Medium/Strong, Raw/One-Euro/Spline/Compare. Pan/pinch and return. Existing widths must scale with the drawing, not the screen. Compare M02 caps/joins, no lift jump or doubled tail. Capture screenshots and `IP_PEN_UP` windows.
4. **Ordering/editing:** draw several crossing/distinct strokes. Sweep the eraser across two separated marks in one motion, then tap at an overlap. Confirm visible topmost hits, untouched nearby ink, exact undo, redo, then undo and draw a new stroke (redo unavailable). Clear then undo: geometry and order must return. Missing/oversized operations must explain failure without changing committed ink.
5. **Flush/isolation:** choose **Save / retry**. Record the acknowledged revision; distinguish “Saving” from “Flushed revision N” and the durable/visible counters. Give A a distinctive camera; create B, draw different ink and give B a different camera. Cycle with **Open next document**. Check ink, order, camera and separate identity; B must never briefly accept an A gesture. History intentionally ends at a successful switch, not at pause/rotation.
6. **Lifecycle:** perform an edit on A, rotate / split screen, background and resume, lock/unlock and exercise EGL recreation. Undo must work through those same-session transitions. Begin and cancel an unfinished stroke. It must not appear after reopen. After a flush, relaunch from a separately authorized process stop **of the verification package only**, verifying the last durable revision and view; persistent undo is not expected. Controlled kill-boundary assertions are in step 2.
7. **Idle and latency:** follow the [M02 capture procedure](M02_TABLET.md) with the verification package substituted. Mark `ip-frames-mark`, allow pending work to settle, mark again, leave idle at least 90 s, dump `ip-frames`; require zero additional callbacks once quiescent. Capture comparable writing/camera SurfaceFlinger windows, settings and refresh period. `ip-document` and `dumpsys meminfo com.infinipaint.demo.m03verify` before drawing, after long strokes, during restore and after settling give native capacity/queue and process memory evidence. Requested VBO storage is not driver residency. Callback/CPU timing is not presentation or physical pen-to-photon latency.
8. **Decision:** provide test output, measurements, screenshot identifiers, exact package/SHA and unresolved limits. Any recovery mismatch, silent loss, cross-document ink, stale pixels, or lost acknowledged edit is a blocker. No claim of million-visible-stroke performance. Written owner acceptance, integration into main and M04 are separate decisions.
