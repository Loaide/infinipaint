## Implemented production paths

1. `document/source_digest.hpp`: fixed-state SHA-256 over the canonical v1 header and original samples, and a separate digest of the exact compatibility vertex bytes. Cache key is document UUID, stroke ID, geometry revision, source digest and mesh digest. The authoritative record still undergoes its existing full validation before activation; an independently valid derived checksum alone does not establish source identity.
2. `tablet/span_store.hpp`: versioned, explicit little-endian 16 KiB pages. A packet contains a CPS1 curve or terminal span, conservative bounds, and the corresponding exact resident vertex extent. Up to 64 packets/leaf and 64 descriptors/branch. Pages carry CRC32C and parent descriptors; reads check contiguity, counts, bounds, ordinal, kind and expected child checksum. Direct ordinal reads of up to 128 packets use a 20-page cap. Spatial traversal returns packets in ordinal order and supports cancellation. A packet carries the mathematical interval, not a newly capped stroke.
3. `tablet/span_cache.hpp`: 256 direct-mapped file slots, one staging file. Build from validated source and byte-match every emitted six-vertex chord to resident v1 geometry. Atomically rename a complete file; persistent entries use file and directory fsync. Dirty files are never reused across process start and may be promoted only following source save acknowledgement. File identity and extent are verified on lookup; selected tree pages are checked on demand. On failure or obsolete work, retain existing exact geometry. Cache data is disposable, not authoritative. Durable file loss merely costs a rebuild. CRCs detect corruption, not hostile tampering. A source/mesh identity is recomputed when the shape changes or is reopened.
4. `native_bridge.cpp::FramePlanner`: publish complete coarse indexed plan first. In its independent worker, read selected span pages for the viewport envelope and publish an optional compatible refined plan. Check epoch/revision/camera; cancel obsolete work. The GL thread never does span I/O. It uses a contiguous conservative resident vertex range covering the selected spline spans (possibly including gaps between nonadjacent hits), with one whole-stroke coverage/resolve operation. Raw, filtered and live paths remain unchanged; composite mode uses the cut for its spline layer. No artificial endpoint caps, per-span opacity or raster substitution. Bound matching is conservative over the entire v1 expanded quad at supported zoom; outside the declared domain, on incompatible byte replay, absent cache, cancellation, corruption or capacity overflow use whole-stroke compatibility geometry. The exact resident fallback is still intentionally present.
5. `tablet/spatial_pages.hpp`, `spatial_delta.hpp`: retain each overlay record's original packed-tree bounding box, compact only the affected packed-tree branches when overlay fills, refit/split/merge and recycle free pages. Counted order tree is not rewritten for spatial compaction. Single-owner scratch generation: final local pages are flushed before success. Bounded write-back within existing 32 slots avoids repeated writes of the same page. A dirty eviction writes immediately; any interruption, corruption, capacity or write failure invalidates both derived roots, never publishes a partly compacted root, and permits exact fallback/rebuild. Oversized edits and pathological overlap may still require full rebuild.

## Resource bounds and scheduling

- Spatial scratch: existing 64 MiB file, 32 MiB dynamic allocation budget, 256 overlay keys, 32 page slots, 4096 rank cache. Compaction maximum 8192 page visits (the rejected next attempted visit is counted). Fixed spatial node recursion limited by validated level. Dirty slots use the existing page payloads, not an additional unbounded write buffer.
- Span cache: separate 64 MiB logical file-length budget including staging, 256 slots, 16 KiB pages, 32 MiB available-filesystem reserve at admission. Combined derived file-length ceilings 128 MiB. OS allocations, actual filesystem blocks/metadata and device write amplification are not measured. One worker-owned opened range at a time in production; no GL-side I/O. A fixed planner reservation includes the working plan and 256 KiB span scratch. No resident mesh ceiling increase.
- 65,536 whole-stroke IDs per coarse plan, 64 optional cuts, at most 256 tree pages per refinement (manifest/build reads are separate), 256 memo slots, one cold source identification/build per plan. Eligible long spline strokes have >=256 chords, and range pruning is limited to v1 coordinate magnitude <=2^24 and existing zoom .1–16. Whole-stroke exact path for ineligible or unmatched geometry. Poll cancellation between small replay slices, pages and packets; no guarantee for blocking OS I/O or fsync. Stable idle does not intentionally schedule periodic work. A dirty entry may remain unpromoted until another compatible refinement visits it after acknowledgement; it is then safely rebuilt if not retained.

## Telemetry

`ip-frames` adds `span_stream` (34 fields) and `spatial_compaction` (15 fields), while preserving existing spatial/order/ink/canonical counters. All cumulative per process. `rawSamples` is sidecar replay samples; `hashSamples` is raw-source identity hashing samples, including cold/cancelled work. `readPages`/`writePages` include build, header and query I/O, not just requested packet payloads. `directReads` counts direct ordinal API success (host exercised; viewport uses spatial traversal). `plannedRows` optional cuts produced, `renderedRows` cut applications including an empty cut; `verticesSaved` logical spline vertices omitted relative to whole-stroke submission, not upload savings, GPU time or presented frames. `queryNs`/`refineNs` include unsuccessful/cancelled elapsed attempts. `fallbackRows` counts explicit eligible-row refinement failure/skip paths, not all strokes or frames with full geometry. `span_stream.bytes` is managed cache file length, not physical RAM; on close its active ledger resets while durable files may remain for re-open. `spatial_compaction.allSpatialWrites` includes initial build; `compactionWrites` is completed 16 KiB writes during compaction; `compactionReads`/`compactionCacheHits` include free-list work. Other counters measure maintenance visits, released/reused pages, splits/merges, overlay rows, faults and latency. Read/write syscalls are not measured physical storage traffic. Source save and original document diagnostics unchanged.

## Measurements and iteration finding

Final direct 128-interval host fixture: 1k samples 4 pages, 10k and 100k samples 5 pages; median about 59/63/67 us, respectively. Actual 100k cache file 26,050,560 bytes; cold build ~99.5 ms. Full hash/replay work on cold creation and source/mesh identity on reopen is still significant. Warm seeks are bounded, not proof of cold physical storage latency or global document scalability.

Localized 256 moves at N=100k: earlier write-through median 1543 writes (25,280,512 logical bytes); final write-back 10 (163,840 bytes), max 12, zero rebuilds; median 12.204 ms vs earlier 13.739 ms in separate host runs. At N=1k/10k final medians 11/10 writes. This is a major reduction in logical write amplification; CPU page scans/checks and worst-case overlap still matter. Actual tablet I/O, thermal and presentation are unmeasured. Coarse exact path can render before refinement; this does not imply 90 Hz sustained pacing.

## Scope limitations and remaining Package 1 requirements

The combined implementation is a **partial integrated candidate**, not the complete approved scalable storage architecture. Specifically:

- Global packed index still contains whole-stroke conservative bounds. Fine span indexing is hierarchical **per record**, lazily materialized for eligible visible long strokes, not a globally packed span R-tree or complete persistent catalog.
- Viewport path really reads verified span packets and uses vertex extents, but **all canonical records and complete compatibility meshes remain resident**. No independent canonical working-set loader, nonresident span-to-GPU geometry materialization or eviction. The prior SQLite ordinal reader still replays the entire requested source record; the new derived sidecar direct API avoids this on warm seeks but does not replace that SQLite path.
- Per-file immutable durable entries and current in-memory paired roots exist, but no complete durable spatial/order manifest tied to a versioned canonical snapshot, no restart without full resident reconstruction. No proof at one million strokes under the configured caps. New derived cache can cost more disk than raw samples, especially for fine spans; quota eviction is essential.
- Local compaction maintains the **coarse** packed tree. Future globally persisted span-tree updates/compaction, global durable generation publication and fully nonresident viewport streaming are open. Do not silently declare those accepted or advance beyond Package 1 on this evidence alone. Package 2 LOD and residency, Package 3 compact Vulkan, Package 4 physical memory/presentation and fidelity gates remain as approved.
