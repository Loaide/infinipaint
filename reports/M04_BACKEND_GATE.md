# Backend selection gate — recommend native Vulkan with compact instancing; owner approval pending

**Decision request:** select native Vulkan with 28-byte chord instances as the candidate for the scalable renderer on the reference tablet. Retain GLES2/v1 as the compatibility and pixel reference. This is a headroom recommendation, **not** a measured increase in visible capacity, a latency win, or authorization to migrate. Canonical ink, sparse paint order, coverage semantics, paging boundaries and the independent camera/input path do not change.

**Why this candidate.** The owner completed the inventory and matched campaign on SM-X626B (Xclipse 540). The GLES2 *path* and GLES 3.2 run through ANGLE on Vulkan; native Vulkan targets API 1.3.279 directly. The [owner's compact analysis](M04_BACKEND_EVIDENCE_COMPACT.md) covers 115 successful runs, 105,000 measured frames and all 9,375 expected GPU samples. All five paths produced identical bytes on the two tested parity fixtures, including reversed paint order. No broader appearance or temporal-stability claim follows.

- **API/path effect:** holding layout compact, native Vulkan reduced median frame wall time by 21.9–36.4% and render-thread CPU by 29.6–43.2% versus GLES 3.2 across the five scenes. At dense64, wall p50/p99 fell from 3.190/4.831 to 2.107/3.451 ms. GPU p50 fell from 0.809 to 0.683 ms there, but was slightly *higher* at dense2. Expanded-to-expanded comparisons also favor Vulkan on wall time. These are implementation comparisons: `gl.cpp` uses a scissored clear then two draws; `vk.cpp` draws the alpha clear, coverage and resolve. Counts are not equivalent units of work.
- **Layout effect:** live suffix counters fell from 216 to 28 B/chord (87.0%); resident pan/dense uploads stayed zero. This is a payload saving, not a measured bandwidth saving. Instancing did not consistently outperform expanded Vulkan: dense64 wall p50 was 2.107 vs 2.065 ms. Do not attribute the CPU win to smaller vertices alone.
- **No presentation win demonstrated:** actual-present feedback yielded 90.096 Hz aggregate and zero estimated missed refreshes by the campaign rule, but median tick-to-present was about 33.3 ms on every path. No independent FrameTimeline join or pen-to-photon result. VKI end PSS/init medians were 49.75 MiB/52.03 ms versus G3I 46.35 MiB/43.66 ms; these are not peaks. On pan, VKI minimal-attribution vs sampled wall medians were 1.963 vs 2.081 ms (~6%); neither causation nor the instrumentation budget is established.
